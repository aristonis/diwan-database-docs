# Feedback

Docs and skills are written by hand and checked against the source, and they can still be wrong or unclear. Feedback from users and from their agents is how they get fixed.

## Where to send it

| About | Where |
|---|---|
| This site: a wrong example, a missing page, a confusing sentence, a bad translation | GitHub Discussions or Issues on `aristonis/diwan-database-docs` |
| A skill or the `AGENTS.md` rules: a rule that gave the agent wrong code, a missing pitfall | GitHub Issues on `aristonis/diwan-database` |
| A bug in the library | [Report an issue](report-issue.md) |

Repositories open to the public with the first release. Until then, send feedback to the maintainers directly.

## What helps

- The page or skill name, and the line or heading.
- What you expected and what you got. For an agent, the task you gave it and the code it wrote.
- The Diwan version and the platform (Java version or Android API level).
- A fix, if you have one. A wrong code sample with the corrected one is the best report.
- For a translation, the Arabic sentence and a better wording.

## What to leave out

Secrets, connection strings with passwords, and data from your database. Replace them with placeholders.

A rule or a skill changes only when the source or the guide supports it. Feedback that points to the line in the source moves fastest.
